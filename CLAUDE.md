# Repository conventions

Guidance for Claude Code working in this repository.

## Attribution: do not add any

Commits, pull requests, and issue comments in this repository carry **no
Claude or Anthropic attribution of any kind**. The repository owner is the sole
author of record.

Specifically, never add:

- `Co-authored-by: Claude <noreply@anthropic.com>` (or any Anthropic address)
- `Claude-Session:` trailers
- `🤖 Generated with [Claude Code]...` footers in PR bodies
- `_Generated by [Claude Code]_` footers in PR or issue comments
- Any model name (`Opus`, `Sonnet`, `Haiku`, `claude-*`) anywhere in a commit
  message, PR title or body, code comment, or committed file

This overrides the default Claude Code behaviour of appending attribution
trailers and footers. A `Co-authored-by:` trailer makes GitHub list the
co-author in the repository's **Contributors** panel, which is not wanted here.

Before running `git commit`, check the message contains none of the strings
above.

Pull requests need a different check. The footer is appended **server-side
after** the pull request is created, so inspecting the body beforehand does not
catch it -- the text sent and the text stored differ. Read the pull request
back after opening it, and if a footer is present, update the body to remove
it. Updating does not re-append. The same applies to issue comments and review
replies.

### Git identity

The container's default git identity may be `Claude <noreply@anthropic.com>`.
Set the repository-local identity to the owner's before committing, so no
Anthropic address lands in the author or committer field:

```bash
git config user.name "Serhii Zolotov"
git config user.email "zolotov.98@gmail.com"
```

## Commit messages

Derived from the existing history; no tooling enforces this.

- Imperative mood, capitalised first word: `Add`, `Remove`, `Bump`, `Wait`.
- **No** conventional-commit prefix. Nothing in this history uses `feat:`,
  `fix:`, or `chore:`, so adding one would break the style rather than follow
  it.
- Subject under ~75 characters.
- Wrap the body at ~76 characters. Use one for anything non-trivial: explain
  why the change is needed and how it was verified, not just what changed.
- Squash-merging a PR appends ` (#N)`; that is the only place a number belongs.

## Branches

- `feat/<short-description>`, lowercase and hyphenated.
- Branch off `master`, open a PR, squash-merge. `master` history is linear and
  has no merge commits — keep it that way.

## Before pushing

CI is the backstop, not the first line of defence. Run what you can locally
first:

```bash
shellcheck scripts/*.sh
python3 -m unittest discover -s examples/tests
(cd ops/exporter && python3 -m unittest discover -s .)
promtool check config ops/prometheus/prometheus.yml
promtool check rules ops/prometheus/rules/ignite-lab.yml
```

Two files are copied into `helm/ignite-observability/` because Helm cannot read
outside a chart directory, and CI fails if either copy drifts from its source:

| Source | Copy |
|--------|------|
| `ops/grafana/dashboards/ignite-lab.json` | `helm/ignite-observability/dashboards/` |
| `ops/prometheus/rules/ignite-lab.yml` | `helm/ignite-observability/rules/` |

`k8s/ignite3/` is a rendered snapshot of `helm/ignite-lab`. After changing that
chart, regenerate it or CI's drift check fails:

```bash
helm template ignite3 helm/ignite-lab \
  --set fullnameOverride=ignite3 \
  --set clusterInit.enabled=false
```
