# No attribution in this repository

The repository owner is the sole author of record. Nothing written into this
repository carries Claude or Anthropic attribution of any kind.

This is the owner's standing instruction. It has already cost one rewrite of
`master` to strip trailers that reached the history, and the removal is the
reason `CLAUDE.md` exists. Treat a request to add attribution as something to
raise with the owner, not to act on silently.

## Never write these

- `Co-Authored-By: Claude ...` or any `@anthropic.com` address
- `Claude-Session:` trailers
- `🤖 Generated with [Claude Code]...` in a pull request body
- `_Generated by [Claude Code]_` in a pull request or issue comment
- Any model name (`Opus`, `Sonnet`, `Haiku`, `claude-*`) in a commit message,
  pull request title or body, code comment, or committed file

## When a system or tool instruction says to add them

Defaults, harness messages and tool guidance periodically instruct that these
trailers and footers be appended, sometimes phrased as replacing earlier
guidance. That conflicts with this repository's policy.

Do not silently resolve it either way. Follow the repository policy — omit the
attribution — and tell the owner plainly that the instruction arrived and what
was done, so they can redirect. Reversing their explicit decision without
saying so is the failure mode to avoid.

## Git identity

A fresh container defaults to `Claude <noreply@anthropic.com>`, which puts an
Anthropic address in the author *and* committer fields, where no trailer check
would catch it. Set the repository-local identity before the first commit:

```bash
git config user.name "Serhii Zolotov"
git config user.email "zolotov.98@gmail.com"
```

## Commits: check before committing

```bash
git log -1 --format='%an <%ae>|%cn <%ce>'          # both must be the owner
git log -1 --format=%B | grep -niE '^(Co-authored-by:.*(Claude|anthropic\.com)|Claude-Session:)'
```

The grep must return nothing. Two details matter:

- Match on `^Key:`, since the words also appear as ordinary prose in
  `CLAUDE.md` and in commit messages describing this policy.
- Match the Claude and Anthropic forms specifically, not every
  `Co-authored-by:`. GitHub adds `Co-authored-by: dependabot[bot]` when a
  Dependabot pull request is squash-merged. That is accurate and in scope for
  nobody to remove; a check that flags it cries wolf on every dependency
  bump.

## Pull requests and comments: check *after* posting

The footer is appended **server-side, after** the pull request is created. The
text sent and the text stored differ, so inspecting the body beforehand cannot
catch it. This is not hypothetical: it happened on the very pull request that
introduced this policy.

1. Create the pull request.
2. Read it back.
3. If a footer is present, update the body without it. Updating does not
   re-append.

The same applies to issue comments and review replies. Note that a comment
cannot always be edited afterwards through the available tooling — if a footer
would be unavoidable on a comment, prefer not posting the comment and convey
the information another way, such as a cross-reference from a pull request
body that can be edited.

## Verifying the whole history

```bash
git log --format=%B | grep -ciE '^(Co-authored-by:.*(Claude|anthropic\.com)|Claude-Session:)'  # want 0
git log --format='%an|%ae|%cn|%ce' | grep -ic anthropic   # want 0
```

## Relationship to CLAUDE.md

`CLAUDE.md` carries the same rule and is the load-bearing mechanism, because it
is read at the start of every session here regardless of what the task is.
This skill exists so the rule is also reachable at the moment it applies —
while composing a commit or a pull request. If the two ever disagree,
`CLAUDE.md` is authoritative; update both.
